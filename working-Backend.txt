CivicRoute Backend Work Log
Updated: 2026-10-29

Purpose
-------
CivicRoute is a Karnataka public-service navigator. The backend should identify a supported service, retrieve its verified catalog entry, compose plain-language steps, validate the result with Pydantic, and return structured JSON. Verified service data is authoritative. The LLM may only rephrase verified steps and must not invent service facts.

Agreed constraints and decisions
--------------------------------
- Supported service IDs: aadhaar_update, income_certificate, civic_complaint. Use unknown for unsupported or ambiguous requests.
- Preserve existing features and integration points; do not remove or rename existing endpoints or behavior without agreement.
- Keep services.json as the authoritative verified service catalog. Do not add unverified facts or silently persist model/search output.
- Supported languages in the existing API: en and kn. Kannada wording needs native-speaker review before claiming full support.
- Gemini is optional. Catalog wording must remain the fallback if generation is unavailable or invalid.
- Never put API keys, secret values, or other credentials in this file. Environment-variable names below are safe to record.
- No frontend files or frontend API types were found in the inspected repository. Therefore no frontend contract could be checked or agreed from repository evidence. The proposed contract below is the requested initial contract; confirm it with frontend/data teammates before implementation changes that could affect integration.

Existing implementation and compatibility mismatch
--------------------------------------------------
The current POST /ask request already accepts question and language with en/kn, defaults language to en, rejects extra fields, and constrains question length to 1–2000 characters. The existing response model does not match the proposed response: it returns service_id, supported, language, answer, steps, and nested service fields (documents, fees, official_links, sources, last_verified). It lacks status, service_name, singular normalized fee, online_option, office_type, grievance, warnings, official_portal_url, and suggested_services. Existing documents are strings; fee and link records use a different shape. The unsupported response currently has answer/steps/service fields instead of the proposed unsupported shape. GET /health is also an existing endpoint to preserve.

No frontend is present to demonstrate whether either response shape is already integrated. Data teammates' agreement is likewise not evidenced in this workspace. This is an integration decision to confirm before changing the current response contract. If the proposed contract is accepted, update with explicit compatibility in mind and retain GET /health.

Step composition progress — 2026-10-29
--------------------------------------
Implemented `compose_steps(entry, language)` in `backend/llm.py` using the Google Gen AI Python SDK Interactions API. The Gemini wrapper is now the only module that imports/calls the SDK; the legacy root app calls the composer without changing its response contract. The model receives only stored verified steps from the selected entry and the requested language. Structured output permits only a `steps` array; Python rejects additional fields, blank items, malformed output, or a changed step count. The prompt prohibits adding/removing/strengthening requirements or creating documents, fees, links, eligibility, offices, deadlines, or legal claims.

Reviewed prewritten Kannada steps are returned unchanged whenever present. Missing API key, provider failure, or invalid output returns stored steps and a warning where appropriate. If the requested language is missing, the original stored steps are returned with a warning. SDK calls use an eight-second timeout, one bounded retry, and `store=False`; logs contain no prompts, keys, or exception details. `GEMINI_API_KEY` is read from backend environment settings only.

Model choice and docs check:
  Default is `gemini-3.8-flash`, centralized in `backend/config.py`; override it with the environment variable `GEMINI_MODEL`.
  Google's current official model guide lists Gemini 3.8 Flash as stable, and the structured-output guide lists support for structured output. The current official Python quick-start uses `google-genai` and `client.interactions.create` with `response_format` schema. Account/project entitlement cannot be checked without invoking the configured account; if unavailable, runtime fallback is safe.
  References: https://ai.google.dev/gemini-api/docs/models ; https://ai.google.dev/gemini-api/docs/structured-output ; https://ai.google.dev/gemini-api/docs/interactions-overview
